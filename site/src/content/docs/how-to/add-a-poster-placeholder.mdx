A poster is the full-quality image shown before playback starts. Start by giving the player a poster URL. Then, if that image takes long enough to load that the empty space is noticeable, add a lightweight placeholder underneath it.

The two images have different jobs:

- The **poster** is video metadata. Video.js resolves its URL and controls when it is visible.
- The **placeholder** is optional presentation. It appears while the poster downloads, then the poster covers it.

## Set the poster on the player

Pass the poster URL to the player, not the media element. The skin draws its own poster above the media and hides it after the user plays or seeks.

<FrameworkCase frameworks={["react"]}>

```tsx
import '@videojs/react/video/skin.css';
import { Video, VideoPlayer, VideoSkin } from '@videojs/react/video';

export function MyPlayer() {
  return (
    <VideoPlayer poster="/poster.jpg">
      <VideoSkin>
        <Video src="/video.mp4" playsInline />
      </VideoSkin>
    </VideoPlayer>
  );
}
```

</FrameworkCase>

<FrameworkCase frameworks={["html"]}>

```html
<video-player poster="/poster.jpg">
  <video-skin>
    <video src="/video.mp4" playsinline></video>
  </video-skin>
</video-player>
```

</FrameworkCase>

The skin gives the poster an empty `alt` by default. If the image communicates information that is not available elsewhere, customize the poster image and describe it with `alt` text. See the <DocsLink slug="reference/poster">Poster reference</DocsLink> for examples.

## Let a media component provide the poster

Some media components can derive a poster from the source. For example, `MuxVideo` creates a poster URL from its playback ID:

<FrameworkCase frameworks={["react"]}>

```tsx
import '@videojs/react/video/skin.css';
import { MuxVideo } from '@videojs/react/media/mux-video';
import { VideoPlayer, VideoSkin } from '@videojs/react/video';

export function MyPlayer() {
  return (
    <VideoPlayer>
      <VideoSkin>
        <MuxVideo
          source={{
            playbackId: 'BV3YZtogl89mg9VcNBhhnHm02Y34zI1nlMuMQfAbl3dM',
            poster: { time: 2 },
          }}
          playsInline
        />
      </VideoSkin>
    </VideoPlayer>
  );
}
```

</FrameworkCase>

<FrameworkCase frameworks={["html"]}>

```html
<video-player>
  <video-skin>
    <mux-video
      src="https://stream.mux.com/BV3YZtogl89mg9VcNBhhnHm02Y34zI1nlMuMQfAbl3dM.m3u8"
      poster-time="2"
      playsinline
    ></mux-video>
  </video-skin>
</video-player>
```

</FrameworkCase>

When the player and media component both provide a poster, the player's `poster` wins. Use the player prop when you need to replace a provider's generated image.

## Add a loading placeholder

A placeholder should be small enough to arrive with the page, such as a short data URL or a tiny inline image. Put it on the same image that displays the final poster. The background paints immediately; the resolved poster appears over it when the image finishes downloading.

Match `background-size` to the poster's `object-fit`. The examples use `contain`; use `cover` for both when the poster should fill its container.

<FrameworkCase frameworks={["react"]}>

Pass a custom image to the skin's `renderPoster` prop. Keep the props Video.js supplies, including the resolved final `src`:

```tsx
import '@videojs/react/video/skin.css';
import { Video, VideoPlayer, VideoSkin } from '@videojs/react/video';

export function MyPlayer() {
  return (
    <VideoPlayer poster="/poster.jpg">
      <VideoSkin
        renderPoster={(props) => (
          <img
            {...props}
            style={{
              ...props.style,
              background:
                "url('data:image/webp;base64,…') var(--media-object-position, center) / contain no-repeat",
            }}
          />
        )}
      >
        <Video src="/video.mp4" playsInline />
      </VideoSkin>
    </VideoPlayer>
  );
}
```

</FrameworkCase>

<FrameworkCase frameworks={["html"]}>

Place an image in the skin's `poster` slot. Leave off `src`: the skin fills it with the resolved poster URL, while the background displays immediately.

```html
<video-player poster="/poster.jpg">
  <video-skin>
    <video src="/video.mp4" playsinline></video>
    <img
      slot="poster"
      alt=""
      style="background: url('data:image/webp;base64,…') var(--media-object-position, center) / contain no-repeat"
    >
  </video-skin>
</video-player>
```

</FrameworkCase>

The placeholder is not a second poster source. Video.js continues to manage one final poster URL and its visibility.

## Own the final poster image

<FrameworkCase frameworks={["react"]}>

Framework image components can render their own placeholder and transition. Pass one to `renderPoster`. The resolved `src` is undefined until Video.js has a poster, so guard it before rendering a component that requires a source.

```tsx
import '@videojs/react/video/skin.css';
import { Video, VideoPlayer, VideoSkin } from '@videojs/react/video';
import NextImage from 'next/image';

export function MyPlayer() {
  return (
    <VideoPlayer poster="/poster.jpg">
      <VideoSkin
        renderPoster={({ src, ...props }) =>
          src ? (
            <NextImage
              {...props}
              src={src}
              alt=""
              fill
              placeholder="blur"
              blurDataURL="data:image/webp;base64,…"
            />
          ) : null
        }
      >
        <Video src="/video.mp4" playsInline />
      </VideoSkin>
    </VideoPlayer>
  );
}
```

Next.js generates blur data for static imports. The poster URL in this example arrives at runtime, so provide `blurDataURL` yourself.

</FrameworkCase>

<FrameworkCase frameworks={["html"]}>

Use the slotted image when you need `srcset`, `sizes`, or a `<picture>`. Once you add your own `src`, `srcset`, or `<source>` candidates, you own the final image and Video.js leaves its source alone. See the <DocsLink slug="reference/poster">Poster reference</DocsLink> for examples.

</FrameworkCase>

## Customize a poster in your own UI

<FrameworkCase frameworks={["react"]}>

If you built your UI from individual components, apply the same override directly to <DocsLink slug="reference/poster">Poster</DocsLink>:

```tsx
<Poster
  render={(props) => (
    <img
      {...props}
      style={{
        ...props.style,
        background:
          "url('data:image/webp;base64,…') var(--media-object-position, center) / contain no-repeat",
      }}
    />
  )}
/>
```

</FrameworkCase>

<FrameworkCase frameworks={["html"]}>

In an ejected skin, put the image inside `<media-poster>`:

```html
<media-poster>
  <img
    alt=""
    style="background: url('data:image/webp;base64,…') var(--media-object-position, center) / contain no-repeat"
  >
</media-poster>
```

</FrameworkCase>

## Troubleshooting

### No poster appears

Set `poster` on the player, not on the nested media element. If you expect the media component to provide one, confirm that its source includes the metadata needed to derive a poster.

### A custom image ignores the player poster

<FrameworkCase frameworks={["react"]}>

Pass the `src` received by `renderPoster` to your final image. If the image component rejects an undefined source, return `null` until `src` resolves.

</FrameworkCase>

<FrameworkCase frameworks={["html"]}>

Remove `src`, `srcset`, and any parent `<picture>` sources when you want Video.js to fill the final URL. Those values tell `<media-poster>` that you own the image source.

</FrameworkCase>

### The placeholder and poster use different crops

Pair `background-size: contain` with `object-fit: contain`, or use `cover` for both. Keep their positions aligned with `var(--media-object-position, center)` when a skin controls poster positioning.

### The placeholder adds too much page weight

Use fewer pixels and stronger compression. A placeholder only needs to preserve the poster's dominant color and shape until the final image arrives.
